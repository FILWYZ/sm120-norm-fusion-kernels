# RTX 5060 SM120 本机调度优化

日期：2026-10-07

## 环境与协议

- GPU：NVIDIA GeForce RTX 5060，Compute Capability 12.0，约 8 GiB。
- WSL runtime：PyTorch 2.14.1+cu130。
- 扩展编译：CUDA Toolkit/NVCC 13.3，TORCH_CUDA_ARCH_LIST=12.0。PyTorch 报告 CUDA 13.0，NVCC 13.3 产生 minor-version mismatch 警告，但扩展编译成功。
- V3/V4 配对基准：FP16、BF16；tokens {1, 16, 32, 33, 64, 128, 192, 193, 256}；5 个独立进程；每进程 10 轮；每个样本 300 次 CUDA Event 计时迭代；V3/V4 每轮交换先后顺序。输入/残差为零、weight 为一，避免 in-place 计时中数据漂移。
- 原始逐进程数据：benchmark_results/rtx5060_local/paired_dispatch/。固定顺序的多实现基线：benchmark_results/rtx5060_local/baseline/ 和 dispatch/。

## 修改与边界

- hidden size 1024 的 Auto dispatch 不再对 33–192 行选 V3，改为 V4；其他 hidden size 继续用通用 V2。
- FP16 256 行的 V3 快约 0.9%，收益不足以抵消新增 dtype/shape dispatch 复杂度，所以仍统一选 V4。
## nano-vLLM 端到端交错对比

使用原始提交 V3 和当前 V4 两个独立构建，在同一软件栈上按 V3/V4、V4/V3 交替顺序各测 5 次。模型 Qwen3-0.6B、FlashInfer Attention、QK Norm+RoPE 使用 Torch 路径、输入 64 tokens、输出 16 tokens、max_model_len 128。batch 为 33 和 64，记录完整结果于 benchmark_results/rtx5060_local/e2e_largebatch_paired/。

| batch | V3 输出吞吐中位数 | V4 输出吞吐中位数 | 配对变化中位数 | Decode 吞吐变化 | 平均 TPOT 变化 | 显存变化 |
|---:|---:|---:|---:|---:|---:|---:|
| 33 | 4544.7 token/s | 4635.5 token/s | +1.40% | +1.79% | -1.76% | 无可见变化 |
| 64 | 7545.9 token/s | 7538.4 token/s | +0.09% | -0.08% | +0.08% | 无可见变化 |

在这组负载中，V4 对 batch 33 有小幅收益，对 batch 64 基本持平。该结果只支持保留本机高并发分发选择，不代表所有形状都有端到端加速；微基准收益不可直接等同于模型吞吐收益。
- 仓库最初记载的环境是 PyTorch 2.11+cu128；这次在当前 PyTorch 2.14+cu130/NVCC 13.3 下编译和测量，结果只对当前运行环境和记录形状负责。
